## Decisions
Use rusqlite with bundled SQLite and zstd level 1. Keep one connection and compressor per store; mirror Go's WAL/NORMAL/busy_timeout=5000, schema, canonical file identity, insert deduplication, max_versions=100 (nonpositive unlimited), pruning and explicit shutdown checkpoint. Load the versioning subsection of config.toml; broader configuration remains outside scope. Rust now includes native C libraries, unlike production Go's pure-Go SQLite/zstd implementations; record that build/portability tradeoff.

Enable history only for interactive or mutating commands, and explicit history queries. Ordinary list/help/version do not create history. Capture loaded revisions before editing and exact committed bytes after replacement while holding the shared file lock. Surface history errors after replacement as committed errors; never roll back or mislabel a committed file. Force-save captures observed overwritten bytes before replacing them. Restore validates its candidate and commits against the current loaded revision, leaving the active document unchanged on pre-commit failure.

The TUI browser lists versions and previews exact saved text, with Enter then y confirmation; it does not claim Go's character-level diff. A 500 ms poll reloads changed files only when idle, without discarding pending input, browser state or unsaved content. Parent task-label edits change only their first line and verify unchanged descendant state/depth. Multiline task queries and destructive parent deletion remain rejected.

The executable comparison retains the original no-history baseline, checks database hashes after CLI and PTY operations, and adds distinct-content edits to the toggle workload so deduplication cannot hide history costs. Report local latency, memory, binary/build/database sizes and limitations. Isolated temporary config directories are mandatory for all tests and benchmarks. A Go test adapter uses the production versioning API to verify snapshot interoperability.
