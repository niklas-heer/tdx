# tdx v0.15.0

Saved views, safer scripting and Markdown edits that leave the rest of your file alone. This is a pre-1.0 release; existing todo files, global configuration and the JSON array output of `list --json` remain compatible.

## What's new

- **Saved views:** set your tag, priority, due-date, completed-task and section filters, then run `:save-view` to name them. `:views` recalls one, `:delete-view` removes one and `:clear-view` shows everything again. Views are stored per file in your configuration directory and never touch your Markdown. To reopen the last view automatically, set `restore = true` under `[views]` in `~/.config/tdx/config.toml`.
- **Manual save:** `--manual-save` and `:manual-save` name the mode formerly called read-only. `--read-only`, `-r`, `:read-only` and the `read_only` setting keep working; the new `[defaults] manual_save` setting takes precedence when both are set.
- **Reliable clipboard:** copying uses `pbcopy` on macOS, `wl-copy` on Wayland, `xclip` or `xsel` on X11 and PowerShell on Windows. It runs outside the input loop with a timeout and shows a clear error when a helper is missing.

## Scripts and automation

- **Richer filters:** `list` accepts `--priority N`, `--due all|none|overdue|today|week|YYYY-MM-DD` and `--section "Heading"` (including subsections), combined with `--status` and `--tag`, in text and JSON output.
- **Retry-safe writes:** `done` and `undone` set a task to a definite state, so repeating them is harmless. All mutation commands accept `--if-revision`, and a stale revision fails before anything changes.
- **Consistent snapshots:** `list --with-revision` returns the tasks together with a revision of the whole file in one envelope (`schema_version`, `revision`, `tasks`). `tdx FILE revision` prints just the token. Ordinary `--json` still returns the same array as before.
- **Shell completion:** `tdx completion bash|zsh|fish` generates static completions that never read your tasks.

## Safer editing

- Editing, moving and sorting tasks now patch only the affected part of your file. Reference definitions, HTML, tables and line endings elsewhere stay byte for byte. Moving or sorting a parent carries its subtasks and body, and bulk edits apply all together or not at all.
- Edits that tdx cannot make safely, such as rearranging inside blockquotes or tab-indented continuations, return an error instead of rewriting the document.
- Reordering unfiltered tasks keeps their nesting.
- Task indexes stay correct around quoted examples that look like checkboxes.

## Terminal fixes

- Inline screens keep a stable frame across modes and resizes, and the selected task stays visible.
- The diff browser's controls stay inside the terminal.
- Applying a saved view restores your cursor to the most recent task, and views keep section labels that are empty.

## Verified releases

Releases are now gated on the portable checks plus native macOS, Linux and Windows validation, including real-terminal tests. Each release publishes `SHA256SUMS` and signed build provenance. The installer verifies the binary against `SHA256SUMS` before replacing an existing installation; check a download yourself with `gh attestation verify <binary> --repo niklas-heer/tdx`. Weekly CI replays structural-edit sessions and keeps replay artifacts when one fails.

## Install or upgrade

```bash
brew update
brew upgrade niklas-heer/tap/tdx
```

For a first Homebrew installation, use `brew install niklas-heer/tap/tdx`. Or install this release directly:

```bash
curl -fsSL https://niklas-heer.github.io/tdx/install.sh | bash
```

The installer defaults to `~/.local/bin`; use `TDX_INSTALL_DIR` for another directory or `TDX_VERSION=0.15.0` to pin this release. It cannot install releases that predate checksum manifests, such as v0.14.0; use Homebrew or download those directly. On Windows, download `tdx-windows-amd64.exe` from this release.

JSON indexes are positions rather than persistent IDs: re-query, or pass `--if-revision`, before issuing a write. The JSON schema can still evolve during pre-1.0 development.
